Everything you are about to see is one company, five people and one month. The people are made up. The rules underneath them are the real Vietnamese ones.

12

Run the payroll

All five · this is the moment the demo is for
38′
Set it up

Before you upload anything, open Settings → Mapping and show them the Employee & contract board: twenty-seven columns of the pay scheme already read from the employee record, the contract, the bank account or the pay period.

The Vietnamese pay rules ask for about forty-five things per person per month. We have taken all but a handful off you. Here is what is left.

Then
  1. Go to Pay Run → Import Data.
  2. Choose the scheme Rize Vietnam.
  3. Set the period to this month, first to last day.
  4. Upload Rize Vietnam - demo pay data.xlsx and load it. Five rows.
  5. Match the employees. Five matched, nothing in error — matched on the employee code alone.
  6. Process. Five payslips.
The point

Open the file's column list on screen, or just describe it. It carries the employee code, six columns of days and hours, and sixteen columns for one-off amounts that are almost all empty.

It does not carry anybody's salary, their dependants, whether they are in the union, their tax residency, their pay grade, their uniform allowance, their health premium or their bank details. Every one of those came off their record.

Put it back

after the demo

Removing the demo data

Go to Settings → Demo data and press Remove demo data. The page lists every record the load created; removing takes out exactly those and nothing else. It does not search for names beginning with "Demo".

If you ran the payroll during the demo, the pay run will hold those five people down and the removal will say so, by name. Delete the pay run first, then remove again.

Loading it again

The same screen loads it. One demo world per company at a time — if one is already loaded it will tell you rather than build a second set on top.

The pay-data spreadsheet is built for the month it is generated in. If you are demoing in a later month, ask for a fresh one; the standard working days and the joiner's paid days both move.

If they ask

likely questions

"Can we use our own spreadsheet?"

Yes. The file is matched on its column headings, not on where the columns sit, so a file with extra columns or a different order still works. The mapping screen is where you tell it which heading means what.

"What happens when someone's salary changes?"

You change their contract. The next pay run reads it. Nothing about the monthly file changes.

"How do we know where a number came from?"

Every payslip records, for every input, whether it came from the file, from the employee record, from the contract, from a connected system, or from the pay period itself. That is shown on the payslip and on the Source screens.

"Is this our data?"

No. Five invented people on a demo tenant. Say so plainly and early — it is the only answer that builds trust, and the delete button is right there.
