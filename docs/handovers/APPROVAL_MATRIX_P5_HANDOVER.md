## 3. Architecture notes

### 3.1 Additive engine change (bump `biz_approval_workflow`)
- `biz.approval.adapter.mixin._approval_process_key_for(self)` (default: returns the class attribute) so one model can serve two catalogue rows (`runonly`/`loads`). `biz.approval.process.connected` considers a model connected if any registered adapter's class key **or** `_approval_process_key_for` can return that key (declare `_approval_process_keys = ('runonly', 'loads')` on the adapter for the static check).
- Engine `submit()` re-verifies the record's current process key at submission; the request stores it.

### 3.2 Downloads and hashes
- `pb.bank.file.action_download()` → recompute sha256 of `attachment_id.raw`, compare with `approved_hash`; mismatch or not approved → refuse "This file is not the approved one. Prepare it again." Content-Disposition via the standard `/web/content` route with the attachment's access token.

### 3.3 Records Desk proposal semantics
- `plan_json` rows: `{emp_id, field_key, old, new, model, res_id}`; on apply compare `old` to the live value (same normalisation `_evaluate` uses); mismatched rows → collected, the request is returned with the list in `return_note`, nothing written (all-or-nothing per proposal, one savepoint).
- Fast lane published for `records` → `apply_changes` behaves exactly as today (evaluate + write + log), plus the request row in `applied`.

## 4. Safety rails
1. No money action (download, release, post, send) without an applied request, except a published fast lane.
2. Hash + control total re-verified at download and at release; run must be `done` (P3 state) for a bank file to be prepared.
3. Records Desk never writes a value whose live counterpart changed since the proposal.
4. Arrivals never create logins or employees from the webhook without an applied request (unless fast lane).
5. No `sudo()` to apply money actions; the applying user is the final approver and must hold `_PAY_GROUPS` (re-check inside `_approval_apply`; if not, block the request with "The final approver needs the Pay & Deliver role" and offer reassignment).
