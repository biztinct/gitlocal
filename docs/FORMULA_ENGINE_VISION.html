Product vision · Formula Engine · July 2026

Your Excel is the configuration.

Every payroll platform on earth asks the customer to abandon the spreadsheet that already runs their payroll and re-express it in a proprietary rule builder. Payobook does the opposite: we take the client's working Excel and make it a living, intelligent, audited system — same mental model, superpowers added. Nothing to re-learn, almost nothing to re-work.

03 The three studios · 1 of 3

Formula Studio, next level

The Cards view stays — it is the best narrative surface for understanding one component deeply. It gains the things power users miss and the things reviewers need. Cards, Grid and Payslip are three lenses on the same hr.formula.rule graph: edit in any, all update.

Raw-Excel mode

A toggle on every card: chips ⇄ raw Excel text with syntax highlighting and the same 260 ms live validation. Consultants who think in Excel type Excel; the chips remain the default for everyone else. Both write to the same excel_formula.

Command palette (⌘K)

Jump to any component by code or name, switch configs, run actions: "explain PIT", "simulate June", "show unused", "diff v12 v13". The Linear lesson: speed is a feature senior users choose products for.

Find & replace across the config

Search formulas, names and codes; replace with preview of every affected formula. Rename-component is a refactor: every reference updates atomically or not at all.

Version rail on every card

The card's right edge shows its history: who changed it, when, and a one-line AI summary ("bracket 2 rate 10% → 12%"). Click to see the visual diff or restore.

Inline docs & legislation links

Notion-style: each component carries a description block, worked example, and a link to the circular/decree it implements. Docs export to the client handbook automatically.

Problems rail

IDE-style panel aggregating every error, warning and lint across the config: circular refs, unused components, hardcoded magic numbers, components that never reach a payslip. Click-to-fix where deterministic.

Beyond Excel, deliberately

Keyboard-first, all the way down

Arrows/Tab/Enter to move, F2 to edit, Ctrl+click multi-select, Shift+arrows ranges, ⌘K anywhere. Roving focus, single input overlay, Vietnamese IME-safe (commits on compositionend).

Typed cells, not strings

Airtable's lesson: a rate cell renders as %, a bracket table opens a bracket editor, a component reference opens a picker. The grid enforces types the engine already knows.

Bulk edit & drag-fill with a safety net

Select five columns → set category once. Drag a formula across allowance columns → server translates references → ghost preview shows all five results before anything commits.

Collapse by category, frozen panes

Fold "Allowances (12)" to one summary column. Header and label column stay frozen via CSS sticky — no scroll-sync JS, no jank.

Scenario columns, side by side

Duplicate any column into a scenario variant ("PIT — 2027 proposal") and compare live values in the same sheet. Promote or discard the variant in one action.

Multiple sample rows

Pin three live value rows — junior, median, executive — and watch every edit ripple through all three. Edge cases stop being an afterthought.

06 Pillar 2

Formula Intelligence: the X-ray layer

Excel's Formula Auditing, rebuilt for a system that actually knows the whole graph. Everything here is deterministic — computed from formula_dependencies and the topological evaluator, shipped to the client once, traversed instantly. No LLM, no network, no excuses.

Impact analysis on click

"Editing BASIC affects 14 downstream components, 6 of which appear on the payslip, across 4,512 employees." Expandable list, click-to-jump. The number that stops a Friday-afternoon mistake.

Execution replay

Time-travel debugging: pick a real payslip, press play, and watch the topological order execute step by step — each component's inputs, expression and result filling in. Pause, step back, inspect. The single best training tool ever put in front of a payroll clerk.

Dependency graph as navigation

The Obsidian move: the graph is a place you work, not a diagram you glance at. Filter by category, highlight critical paths (longest chains), spot the hub components everything hangs off.

Circular refs, explained

Not a flag — a sentence and a picture: "T → Q → P → T. PIT depends on TAXABLE, which subtracts PIT." With the two standard fixes offered: split into pre/post components, or iterate-to-convergence mode.

Execution order & timing

The evaluator's actual order, visualized as a timeline with per-component compute cost across the last payrun. Slow VLOOKUP-style lookups stand out; optimisation suggestions attach to the offenders.

Unused & orphan detection

Components nothing references and nothing prints; inputs no formula reads; constants that duplicate a rate table. Each with a safe one-click archive. Configs stay clean for years, not months.

Config health score

The existing health ring, made honest: weighted from validation state, cycle-freedom, test coverage, unused count, hardcoded-number lint. Bureaus triage fifty clients by sorting on it.

Change heatmap

Which components change most often, which formulas fail tests most, which cause payrun exceptions. Where the heat is, that's where review attention goes.

The reimagined import, end to end

Single drop

One drag of the workbook. Header detection, merged-cell categories, cross-sheet resolution and constant detection run instantly — the analysis the wizard already does, presented as one animated moment, not seven screens.

Resolved-formula preview

Every component shown as Excel original vs engine formula, side by side. Nothing has been committed. What used to silently become 0 is now a red row.

Broken-reference triage

Each unresolved reference gets a fix action: map to a component, convert to input, acknowledge as zero, or skip. Join-key health check flags fragile primary-key matches before they eat a row.

Confidence score, then commit

The weighted score (resolution ratio, would-be zeros, column match, key match) gates the import. Below threshold, PayAI reviews the suspicious rows and says why.

Shadow Parallel Run

Historical result sheets recomputed through the engine, verified cell by cell. Discrepancies clustered by cause, not listed by row. The client signs off on evidence.

10 Pillar 6

Trust Layer: change without fear

Payroll's deepest emotion is fear of the silent mistake. The Trust Layer makes every change visible, testable, reversible and signed — which is what finally lets non-consultants edit their own payroll.

Version history with visual diff

Every formula save is a version. Diffs are token-aware — "0.10 → 0.12 in bracket 2", not a wall of red/green text. Restore any version; compare any two config snapshots.

Simulate before activate

Any draft change runs against last month's real inputs: a delta distribution across all 4,512 employees, biggest movers first, zero-change count. "This edit changes nobody's net pay except the 3 people it should" — as a chart.

Scenario sandboxes

Branch a config ("2027 minimum-wage increase"), edit freely, simulate, then merge or discard. Git semantics without git vocabulary.

Testing framework, continuous

The Test workbench grows CI habits: samples auto-run on every save, red before wrong; coverage view shows which components no test exercises; boundary tests generated from bracket analysis.

Sign-off workflow

The lifecycle rail becomes a review: changes bundled into a named release, reviewer sees diffs + simulation + test results in one screen, annotations pin to specific formulas, approval is recorded and immutable.

Audit narrative, auto-written

Per period, per config: "June 2026 — 3 formula changes (PIT bracket update per Decree 65, approved by L.Anh), 0 test regressions, parallel-run variance 0.0%." Auditors read prose, not logs.

Accessibility, mobile, performance — commitments, not chapters

Accessible

Full keyboard operation of every studio; visible focus everywhere; status never encoded by colour alone (icons + text); WCAG AA contrast on the locked palette; reduced-motion honoured in every animation including dependency tracing.

Tablet-ready, mobile-honest

Configuration is a desktop craft; review is not. Tablet: read-only studios, full approval flow, simulation review. Phone: approve/reject releases, read explanations, payrun alerts. No fake mobile editing.

Fast by architecture

Graph shipped once, traversed client-side; virtualized rows past 60 components; debounced single-employee preview (the existing 260 ms pattern); simulation chunked server-side like the payrun wizard; import preview capped with expanders.

14 From vision to commit

Phase-1 build plan

Tier 1, planned to file level against the live codebase and ready to execute — full detail in docs/PHASE1_FORMULA_ENGINE_PLAN.md in the repo. Build order chosen so the dependency-graph API built first powers both the grid and the import preview.

Formula Intelligence v1 · 4–6 days

New get_intelligence(config_id) + get_impact_analysis(rule_id) RPCs on pb.formula.studio (reuse the evaluator's topological sort). Insights section on the editor card, execution-order + unused panels, circular-ref explainer. Client-side BFS helpers become the grid's highlight primitives.

Grid Studio v1 · ~3 weeks

New lean OWL grid (grid_studio.js, formula_bar.js, cell_autocomplete.js) evolving the studio's existing read-only grid view — the dormant legacy widget is harvested for ideas, not resurrected. CSS-sticky frozen panes, roving focus, IME-safe editing. New RPCs: bulk_update_components, translate_formula (drag-fill with ghost preview).

Import Confidence · ~1.5 weeks

Mixin multisheet_import_preview.py (never grow the 3,814-line wizard): preview lines with original-vs-resolved formulas, fix actions, weighted confidence score. Extends the existing review step; nothing commits until confirm.

Mapping upgrades · ~1 week

Mid→end auto-suggest (exact code → normalized → name similarity ≥ 0.75) with accept-all. API mapping gains a field browser fed by real connector payloads plus batch-test against a sample employee — silent nested-path failures become visible errors.

AI quick wins · 3–4 days

explain_formula_ai(rule_id, lang) EN/VI with the deterministic _explain() floor; ai_review_import over the preview lines with rule-based fallback. Explain button on the card; AI review on the import confirm step.

Polish & verification · ~3 days

pb_coach tour steps for the new surfaces; full validation against the pb_demo VN world (4,512 employees, 30.5k payslips) via Chrome MCP: hand-traced impact counts, keyboard grid round-trips, Thaco template import with confidence gating, batch recompute regression check.

Guardrails carried from the plan: engine/wizard/mapping server code stays in pb_hr_payroll_formula (headless-installable); all cockpit UI and studio RPCs in pb_formula_studio; manifest version bumped on every asset change; grid state keyed by component id, never array index.
