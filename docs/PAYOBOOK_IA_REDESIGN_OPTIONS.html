The rail is an inventory, not a flow

PAY RUN holds ten items that mix a daily verb (Run Payroll), month-end audits (Proration, Retro), an offboarding tool (Full & Final) and a misfiled report. Nothing tells a new user what order things happen in, or which four items they will actually touch this week.

Eight doors to Integrations, three visual styles

Connectors are reachable from the Setup rail, the Import cockpit's tiles and cards, two different cockpit link sets, a stock onboarding modal, a hidden legacy menu, and Formula Studio pickers — and the back button lands somewhere different depending on which door you used. Your instinct was right.

Four front doors to analytics

Insights, Explorer and Workforce Analytics sit side by side in the rail; Payroll Report hides inside PAY RUN; and the Dashboard's own hero button opens a fifth, legacy analytics surface. Same questions, five places to ask them.

Two design worlds in one product

11 screens are stock Odoo (the whole Planning section, most of Admin, the Govt Reports wizard), and 16 good cockpits leak into legacy lists through “Open full list →” and “Advanced form” buttons — which is exactly where the WOW feeling dies.

The good news

The sidebar is fully data-driven (pb.sidebar.item records, no code), and the Mission Control shell already proves the hub pattern with 8 absorbed cockpits. Every option below is mostly re-plumbing and reuse, not rebuilding.

Found while auditing — worth fixing regardless of option

  • “Employee/Contract Mapping” never actually retired — its active field is set with the string "False", which Odoo reads as true. It still renders in SETUP.
  • ADMIN sequence collision — Audit and Menu & Sidebar both sit at sequence 30; their order depends on install order.
  • Sidebar highlight steal — Import Data and Integrations both claim hr.integration.connector, and last-writer-wins decides which one lights up.
  • Orphaned cockpit — a bespoke Pay Runs cockpit exists in pb_payruns but nothing points at it; the rail opens the native kanban instead.
  • Payroll Settings is unreachable — the res.config.settings screen has no rail item and its native menu is hidden.

Three options

Each demo is interactive — click rail items, lenses, the ⌘K button and the cog.

Option A — Six Missions + a Settings cog

The Workforce pattern, applied verbatim to the whole product. The rail shrinks from 37 items to six domain hubs — Home, Pay Run, People, Workforce, Insights, Compliance — each opening a Mission-Control shell whose lens rail carries the old items as one-word lenses. Everything that is configuration (Formula Engine, Structures, Statutory, Integrations, Admin) leaves the rail entirely and lives behind the top-right cog, the way you suggested. One object, one door.

Interactive mockup — click the rail, the lenses, the cog and ⌘K

Why it works

  • 37 items → 7 + cog. A new user sees six words and understands the product.
  • Zero retraining loss — every current label survives as a lens; muscle memory transfers (Payslips is still called Payslips).
  • Cohesion by construction — every hub is the same shell users already love in Workforce: dark command bar, lens rail, needs-you dock, ⌘K.
  • One-door law — Integrations exists only inside Settings; Import, Studio and connectors deep-link to it with a back chip.
  • Cheapest to ship — the sidebar is data records and the shell is clonable from pb_mission.

Trade-offs

  • Cross-hub jumps (Payslips → Employee) cost one extra click — mitigated by making ⌘K global.
  • Pay Run hub sits at the 8-lens comfort ceiling; adding a ninth later forces a split.
  • Moving Setup off the rail changes where four items live — a one-time “where did Formula Engine go?” moment for existing users (cog badge + palette aliases soften it).

Option B — The Cycle: a rail that mirrors the payroll month

Payroll is a monthly ritual, so the rail becomes the ritual: Prepare → Run → Review → Deliver → Close, numbered, with live stage states for the current period — the sidebar literally shows you where this month stands. Domain hubs (Workforce, Insights, Studio) sit below the fold. This is the pattern Gusto and ADP use for their run flows, promoted to the whole IA.

Interactive mockup — note the stage tracker and per-stage state dots in the rail

Why it works

  • Matches the operator's mental model — a payroll admin thinks in month-stages, not modules.
  • The rail is a status display — stage dots answer “where are we?” before a single click. Genuinely novel; no Odoo product does this.
  • Perfect for juniors — the UI itself teaches the process; pairs beautifully with Learn.

Trade-offs

  • Real screens straddle stages — Payslips matter in Run, Review and Deliver; Approvals span Review and Workforce. Every placement is a judgment call users may disagree with.
  • Domains don't fit stages — People and Workforce data are “always”, so they get shoehorned into Prepare or exiled below a divider.
  • Needs period-state plumbing — stage tracking must be computed and kept honest per period, or the WOW becomes a lie.
  • Biggest retrain of the three for existing users.

Option C — Command Deck: four hubs and a keyboard

The radical cut, in the spirit of Linear and Raycast: the rail holds only Home, Pay, People & Time, Insights plus Settings. Everything else is reached through a global ⌘K palette (already built for Workforce — just mounted app-wide) and an “All surfaces” drawer on the brand button. Navigation becomes something you type, not something you scan.

Interactive mockup — try the ⌘K button and the grid button (top-left of the command bar)

Why it works

  • Maximum calm — four words on the rail; the product feels smaller than it is.
  • Power users fly — every surface, person and action is two keystrokes away.
  • Scales forever — new features join the palette and drawer without fighting for rail space.

Trade-offs

  • Wrong audience risk — payroll operators in VN plants are mouse-first; search-first navigation hides structure novices need to see.
  • Overloaded hubs — folding Compliance into Pay and Workforce into People & Time pushes both past the 8-lens comfort line.
  • Two new idioms (palette-first + app drawer) to teach, on top of the hub shell.

The flow doctrine — how archaic wizards become WOW

Applies to every option. Four repeatable patterns, each cloned from something already shipped and loved.

1 · Stock modal → full-screen stepped flow

The Govt Reports “Generate” button opens a 30-field stock Odoo modal — the single worst screen in the product. It becomes a Run-Payroll-style full-page flow: Choose filing → Scope → Generate & deliver. Same treatment for Integration onboarding, Formula Excel import and Planning's Tag wizard.

3 · The one-door law

Every object gets exactly one home. All other references become deep-links that carry a back chip, so the back button always returns where you came from — killing the “same cockpit, different back button” bug the audit found between Import and Integrations.

4 · Same chrome everywhere

The remaining off-system screens join the kit: Payroll Report drops FontAwesome and its duplicate breadcrumb; the Planning dashboard adopts pbim tokens; native employee/contract forms get drawer summaries with a single, honest “Open HR record” escape. Destructive confirms stop using window.confirm() and use the shell dialog.

  • Re-skin: Payroll Report, Planning dashboard, wizard family
  • Drawer-wrap: employee, contract, connector, statutory records
  • Retire: every “Advanced form” button that duplicates a cockpit feature
  • Unify: one confirm dialog, one toast, one empty-state style
Recommendation

Option A — Six Missions… with B's heartbeat and C's keyboard

Ship Option A as the skeleton. It delivers exactly what you asked for — the Workforce drawer design applied to everything, Settings behind a cog, a rail a new user can read in five seconds — at the lowest risk and cost, because every label survives and the shell already exists. Then steal the best organ from each rejected option: from B, the period tracker becomes a widget in the Home and Pay Run hub headers (“August · stage 2 of 5”), giving you the lifecycle WOW without betting the IA on it; from C, the ⌘K palette goes global — it is already built in the Workforce kit and just needs mounting app-wide. Combined with the four flow-doctrine patterns, this takes the product from “10 WOW screens with 27 trapdoors” to one coherent system.
