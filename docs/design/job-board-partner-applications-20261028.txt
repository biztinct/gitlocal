Payobook: practical job-channel activation guide
Reviewed 28 October 2026 against all 29 keys in pb_hiring/services/board_catalogue.py.

This is the owner/implementation team's working guide. No application has been
submitted, agreement accepted, subscription purchased or provider approval received
through this review. Public evidence of another ATS's integration does not confer
access on Payobook. The steps below include proposed requests, not provider promises.

What the customer should eventually experience
Select a channel -> connect their employer account using the provider's approved
method -> confirm the posting package -> publish -> receive applications.
Payobook owns partner registration, connector development, hosting, certification
and maintenance. Employers own their company verification, subscription and consent.
There is no universal developer-app registration or universal password connection.
Some providers provision apps; some issue employer keys; others accept feeds.

Current product baseline
The catalogue and setup-progress tracking are deployed. LinkedIn and SEEK have
connector code but still require approved platform access and employer activation.
Careerjet/Jooble redirect-apply XML feeds are implemented but acceptance is pending.
Google JobPosting markup exists; Indexing API notifications are not configured.
Other channels need an approved specification and implementation before automatic
publishing/intake can be offered. Manual tracking does not enable an API.

Start here: one Payobook application pack
Owner supplies: legal entity name and registration country; named business contact,
role, business email and phone; company size/location; accurate customer count and
job volume; pilot employer if available. Do not invent customers or volume.
Technical team supplies: product description/demo, supported countries, proposed
posting/application workflow, actual callback URLs, privacy/security contact and
provider-specific test plan. Callback URLs must be implemented before registration.
Credentials belong in approved secret storage, never this guide or setup notes.

Suggested sequence (Payobook recommendation, not provider-mandated ordering)
1. Prepare the identity/contact pack once. Begin with Zwayam Amplify below: one
   conversation can cover Naukri, hirist and iimjobs.
2. Apply to SEEK, TopCV and ITviec; open LinkedIn/Indeed applications concurrently
   because their approval is a separate dependency. Obtain a pilot employer.
3. Submit accepted public-job feeds to Careerjet/Jooble and verify careers domains
   for Google. These do not depend on building every premium-board connector.
4. Send targeted scope requests for the remaining channels. Request a board-by-
   board coverage quote from Broadbean and LogicMelon before choosing either.

Every request below should include this short introduction
"Payobook (https://payobook.com) is an applicant tracking and hiring platform.
We are seeking an approved integration for our employer customers. Payobook will
build and maintain the connector; employers will authorize their own accounts.
Please route this request to your ATS integration/technical partnerships team."
Then append the channel-specific request below. Confirm partner fees, employer
fees, sandbox access, certification and production activation before committing.

First application: Zwayam Amplify owner walkthrough
1. Open the item 03 link and reach Request demo. If the page blocks automated access,
   use a normal browser or the existing employer's Naukri account manager.
2. Choose Amplify where offered. Use the actual legal entity and business contact.
   Company size/location describe Payobook's legal business, not a hypothetical client.
3. Use item 03's request in the message field if available, otherwise in the follow-up
   conversation. Explain that Payobook is the ATS vendor and identify a real pilot.
4. Owner reviews and submits the completed form. Save the receipt/reference and date.
5. Record status Requested in the Naukri guide, with related hirist/iimjobs notes.
6. On response, obtain the named integration contact, technical docs, sandbox and
   per-board entitlement quote. A sales/demo response is not production approval.
7. Payobook implements/tests the approved connector. Then guide the pilot employer
   through its key/authorization setup and a controlled live posting.

How we determine that a channel is actually usable
For each approved API: connect the correct employer, publish one authorized vacancy,
observe the external ID/listing, update it, receive a consented test application with
correct employer/job/source/CV mapping, handle retries without duplicates, close it,
and verify disconnect stops access. Test only capabilities in the approved scope.
For feeds: verify provider acceptance, real listing, correct redirect application
and source attribution, and removal after the provider refreshes.
For candidate-only integrations: verify job mapping and candidate delivery; do not
label the channel as automatic publishing. For Google, validate markup/indexing
separately; an API notification is not a guarantee of a search-result appearance.

Track per provider: owner, contact route, sent date/reference, agreed countries and
capabilities, commercial requirements, approval/docs location, sandbox, connector
status, pilot employer, production approval and verified test result. Never store
secret values here. All external applications remain Not submitted in this review.
