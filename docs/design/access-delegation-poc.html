Does module-specific access fit leading products?

Yes—as a contextual entry point into one permission catalogue. Zoho groups profile permissions by module, and Microsoft’s role editor organizes privileges around apps and tables. These support reducing the administrator’s working scope. The exact Hiring → Settings placement is our design recommendation, not a claim that every vendor uses identical navigation.

Zoho · Manage profile permissions ↗ · Microsoft · Create or edit a security role ↗

A Hiring head should see Hiring’s roles, profiles, resources and hand-overs when separately authorized to administer them. Global Settings provides a grouped overview. Shared roles retain their owner; local administrators cannot widen another module’s permissions. Backend authority checks must enforce this boundary, including through direct URLs and APIs.

Profiles are included in all three options. Studio manages reusable packages; Guided Setup chooses and assigns a package; Passport explains the assigned profile and its role sources. Terminology differs by vendor: Zoho profiles hold module permissions; Salesforce uses profiles, permission sets and permission-set groups. For Payobook, a profile that references existing roles avoids duplicating policy controls.

How the proposed permission model should behave

Account type is Employee, Staff or External. Access profile is a reusable package of existing roles, such as Recruiting team. Role carries the action, record and field policies. Profiles reference those roles; they do not copy CRUD or field switches into a second competing layer. Delegation is a bounded temporary grant. The existing pb.role.profile model already represents a role, despite its technical name; preserve that identity and introduce profile composition separately. The first design used “profile” too narrowly for account type; this revision corrects that vocabulary.

Resolve existing groups, direct grants, roles and active delegations first. Existing Odoo ACL grants are additive, group record rules combine by union, and global rules constrain them. “None” in one role therefore means “this role does not grant it”; another source can still allow it. Show that source, and never promise that a simple unchecked box is a universal denial.

Company boundaries remain mandatory. Validate ownership and company on creation and on updates that move a record. “Own” needs an explicit mapping per resource: employee relation, expense claimant, or another business owner; creation author is a different condition. Unsupported mappings should block publication. “Team” needs a resource-specific definition: a recruiting team for Hiring, or self plus direct reports for People. Never infer a whole reporting hierarchy silently.

Enforce field restrictions on the server across forms, lists, exports, reports, imports, API calls and attachments. Native field group restrictions can protect field access; per-role read-versus-write, per-record fields and masking need additional enforcement. A required hidden field needs a safe server default or must make creation unavailable. Keep workflow approval, export, mass update and bank-file generation separate from ordinary editing.

Delegation must stay within the lender’s effective grant and company boundary, expire at an explicit timezone-aware instant, prevent onward lending by default and preserve independent access. Review high-impact grants and conflicts such as preparing and approving the same payroll. Compute expiry at authorization time as well as scheduling cleanup; the current date-based expiry behavior should remain clearly documented until upgraded.

Reference: Odoo 19 · Security model. Simulator logic in this document is intentionally small and uses fictional records; it is not the Odoo permission evaluator.

Recommendation & choice

Choose Studio for the main experience.

It preserves the current product’s strengths while reducing the role-list overload. Use module-local entry points for daily work and a global directory for cross-module administration. The comparison is a design judgment, not measured usability data.
