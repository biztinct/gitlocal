# Employee home: company feed and a visible time clock

The home uses a broad reading column for announcements and a 390px right rail for the clock, schedule, leave and pay. Urgent actions sit above the feed. The previous large empty pay card no longer dominates the first screen. At narrow widths the order becomes clock, urgent actions, feed, team, leave and pay. Existing service links remain below.

Research reviewed on 8 November 2026:

- [Viva Engage announcements](https://support.microsoft.com/en-us/viva/engage/notifications-and-announcements-in-viva-engage): distinguish official updates within the conversation feed.
- [Workvivo activity feed](https://support.workvivo.com/hc/en-gb/articles/4918159867421-Activity-Feed): readable chronological posts, comments, reactions and moderation.
- [Staffbase widgets](https://support.staffbase.com/hc/en-us/articles/25488044747026-Overview-of-Widgets): combine a news feed with useful links and compact employee services.

The feed shows the latest three announcements actually delivered to the employee, with a sender, company, timestamp, subject, excerpt, optional poster, read link, like count and recent comments. The notice board opens older posts. Comments remain inside the existing announcement audience. An employee can remove their own comment; an HR manager who is also a recipient can moderate within their allowed companies. Removal archives comments. No emails or notifications are generated by these interactions. Posting an official announcement continues through the existing HR communications workflow.

Useful content for this area includes leadership/company news, policy reminders, team achievements, celebrations, event notices and learning reminders. These are content suggestions, not fabricated sample posts or automatically disclosed birthdays. Polls, employee-authored top-level posts, pinned posts and subscriptions are possible later extensions; they are not part of this release.

The elapsed clock updates every second from the server-corrected clock-in timestamp, and catches up after a suspended tab. Home and the clock page display the most recent attendance session's start and finish GPS, timestamps and explicit map links. Missing coordinates show “Not recorded”; an open session's end location is pending. Browser location is requested afresh at each punch only when the company's existing tracking setting is enabled. Denied or unavailable GPS does not block clocking. Historical locations are never invented.

Validation covers second/minute rollover and device clock skew, location serialization and ownership, announcement audience checks, duplicate comments/likes, input size, escaping, moderation, and portal rendering. Deployment covers payobook, payobook_template, p0clone, rize, and owner-confirmed sudima, preserving the shared server's standard addons and retirement archives.

Clock-out correction (9 November 2026): the old 60-second punch debounce also rejected valid immediate checkouts. Both clock forms now submit an explicit in/out action and the displayed attendance id. Replays are idempotent, stale forms cannot change a later session, and overlapping portal punches serialize per employee. A successful checkout stops the live timer immediately on the resulting page. No minimum session duration applies.
