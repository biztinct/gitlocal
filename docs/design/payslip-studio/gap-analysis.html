A template needs both the page design and explicit live field bindings

The supplied PDF can be replicated. The previous import algorithm cannot represent it faithfully: it waits for Roman-numbered section headings and then rebuilds every row into one fixed four-column payroll table. The client has unnumbered headings, two independent label/value pairs per row, and empty value cells. Consequently, the original importer treats the body as header text and discovers no payroll rows.

What the supplied document contains

The sample is one US Letter page (612 × 792 points), with a logo, right-aligned employer registration details, a bilingual dated title, five green section headings, 23 value locations, two net-pay currency rows, a confidentiality note and a footer near the bottom of the page. Value locations comprise six employment facts, two day counts, seven earnings/allowance fields, four insurance/union deductions, a dependent count, income tax and two net amounts. Blank cells are intentional template slots, not evidence that a field is absent.

Architecture and invariants

Read: bundled PDF.js renders up to eight pages locally, retaining text positions and producing JPEG artwork. Raster line detection proposes value rectangles. The server validates the document and independently proposes metadata/component bindings. No live layout is changed by analysis.

Review: the import screen exposes confidence and choices. An explicit import saves the artwork and selected bindings, retaining uncertain slots as covered blank fields. The designer edits a local draft; Save validates and persists it atomically. Cancel discards editor changes.

Render: one server value resolver reads computed values by component ID and live employee/contract/period facts. Browser preview and native PDF rendering receive these resolved values, the same field geometry and embedded font families. Native rendering avoids fixed A4 margins and never fetches external artwork.

Preserve: payroll formulas, employee data, sample inputs, component roles, section assignments and the older rich document remain unchanged when a visual template is imported. The visual document takes precedence. Removing it reveals the previous design.

Limits that remain explicit

No importer can infer an arbitrary customer's payroll meaning or missing business data reliably. Scans, borderless forms, unusual nested tables and faint rules may need manual placement. The visual mode preserves arbitrary artwork; it does not turn every decorative line into a vector editing object. Static artwork is rasterized at up to 144 dpi / 2400 pixels on the longest edge; original static labels are not searchable PDF text. Editable text uses three Unicode font families. The existing rich editor remains available for structural table and prose editing.

Use blank or redacted samples: source artwork is retained, and populated source values must be covered wherever they should change. Unbound fields and missing values print a dash. The sample's technical advisory allowance, payback salary, other allowance/bonus, contract-versus-paid transport/phone allowances, and USD net need explicit source decisions where the configured payroll has no unambiguous equivalent. No missing rule or exchange rate is invented.
