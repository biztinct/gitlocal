Hiring connection activation

Location: Set up hiring > Hiring connections, as Talent lead.
The code deploys disabled connections. A saved configuration is not a passed
check. Configure, Check, then Enable. Run controlled provider tests before use.

Hosting decision still required
Recommended starting point: a separate 8 GB RAM / 4 vCPU host, one CV at a time.
Allow 2 GB for Documenso and budget 4–6 GB for CV conversion, then measure peak
use on representative CVs. 16 GB gives more headroom for OCR/concurrency.
If sharing the current Odoo host, recommend 16 GB overall. This is capacity
planning, not a measured production guarantee. No new host has been purchased.
Documenso vendor requirements: https://docs.documenso.com/docs/self-hosting/getting-started/requirements

1. Signing
Deploy Documenso using its official self-host guide and supported envelope API.
Provide HTTPS hostname, PostgreSQL, verified SMTP and a signing .p12 certificate.
Create the team API key and a random webhook secret. Enter these in the guide.
Register the displayed callback and X-Documenso-Secret value with Documenso.
The API check reads the envelope list. It does not prove SMTP or signature
certificate operation. Use a synthetic offer and controlled test recipients
for the first signature and signed-PDF archive check.
Offer flow: country setup > agreed offer > Prepare signing draft > open
Documenso > place signature fields and review > tick reviewed > Send.
Cancel before editing pay lines; completed offers require a new revision.
Poller verifies provider state and signer identities before filing once.
An unsent draft can be cancelled/deleted; the audit history retains its ID.

2. CV extraction
Build services/recruit_cv on the separate service host. Follow its OPERATIONS.
Supply HTTPS URL/key, Check and Enable. New CV attachments identified as CVs
queue extraction. Existing CVs use the Extract CV button. Recruiters review
skills, employment and education before applying. OCR/indexed text is searchable.
No candidate ranking, inferred demographic attributes or inferred proficiency.
An unrecognised employment section stays blank; extracted full text remains
reviewable. Test real EN/VI/ID PDF, DOCX and scanned samples with permission.

3. Calendars
Configure the official Google/Microsoft OAuth application in Odoo Calendar.
Rize IT supplies application credentials/redirect URI setup and tenant consent.
Each organiser connects their own calendar; panel free/busy access is required.
Google and Microsoft SDKs are isolated in /odoo/vendor/hiring-calendar-sdk.
Install the rehearsed lock via pip --target, then install-calendar-sdk.sh.
The SDK runner receives tokens on stdin; it does not replace Odoo dependencies.
Use Find panel availability on a candidate, select panel/window/timezone, copy
the expiring link. The link shows the browser timezone and checks again at booking.
Calendar time moves create an audit record; the recruiter confirms the reason
and Internal/External classification. External diary ownership does not reliably
identify who requested a move. Live Google/Outlook consent/sync tests remain due.

4. WhatsApp and email
Meta requires a verified phone/WABA, system-user token, app secret, callback
verification token and approved four-body-parameter template. Parameters:
candidate name, role, local interview time, joining details. Provider fees apply.
Run Check, register the callback, then Enable after a controlled test.
Record candidate WhatsApp consent and evidence on the candidate form.
Reminders use the existing 24h/30m switches. Unknown outcomes are not retried
blindly. View accepted/delivered/read/failed/unknown in Interview > WhatsApp delivery.
Email keeps Odoo's existing SMTP/OAuth integration and editable templates.
Connection testing does not send email. Sender DNS and inbox delivery need the
approved Rize mail account and controlled test inbox. Existing mail switches
are preserved. No messages were sent to real candidates during implementation.

5. Native configuration
Stage visibility: TA Lead selects stage/audience/parts. HM/panel policies apply
only to those related to the candidate. Named groups need existing request
access. Matching policies replace individual shares for that stage. Agencies
retain their restricted portal. Feedback embargo and resume-bank restrictions stay.
Cover approvers: name TA Lead, Head of HR fallback and dated absence in Hiring
rules. Country assignment notices include the designated TA Lead. No org-chart
manager fallback is assumed for new cover requests.
Country offers: administrator configures approved payroll inputs/employer
outputs, effective dates, country letter and counter-signatory. HR/Finance
must approve rates, defaults and templates. No statutory rates are guessed.
Employer-cost output is an estimate, not a payroll posting. All required inputs
must be supplied. One-time items affect first-year cost, not recurring monthly cost.
